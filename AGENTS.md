# AGENTS.md

Guidance for AI coding assistants and humans working in this repository.

Kandy is an internal Kantega tool: local speech-to-text with meeting summaries,
macOS only, Norwegian-first, Whisper-only. It is a fork of
[cjpais/Handy](https://github.com/cjpais/Handy) (`upstream` remote). There is no
community process. Do not reintroduce Windows or Linux support, non-Whisper engines, LLM
providers other than the Kantega LLM proxy, webhooks, or a debug pane.

## Commands

```bash
bun install
bun run tauri dev          # app in dev mode
bun run tauri build        # production build
bun run lint:fix           # ESLint
bun run format             # Prettier + cargo fmt
bunx tsc --noEmit          # type check
bun run check:translations # en/nb key parity
cd src-tauri && cargo clippy && cargo test
```

Model setup if the first `tauri dev` cannot download Silero VAD:

```bash
mkdir -p src-tauri/resources/models
curl -o src-tauri/resources/models/silero_vad_v4.onnx \
  https://blob.handy.computer/silero_vad_v4.onnx
```

Platform prerequisites and common build errors: [BUILD.md](BUILD.md).

## Architecture

Tauri 2. Rust backend, React/TypeScript frontend. Frontend calls the backend
through Tauri commands; the backend pushes state through events.
`src/bindings.ts` is generated by tauri-specta on `cargo run` and must never be
edited by hand except to keep `tsc` green until the next regeneration.

Pipeline: audio → VAD → Whisper → filler-word removal → optional LLM
post-processing (Kantega LLM proxy) → clipboard paste.

### Backend `src-tauri/src/`

- `lib.rs` entry point, Tauri setup, `collect_commands!`.
- `main.rs`, `cli.rs` CLI parsing (clap). `signal_handle.rs` shared
  toggle/cancel logic for CLI and signals.
- `settings.rs` `AppSettings`, defaults, `SecretMap` (redacting map for the
  LLM proxy key). Persisted with `tauri-plugin-store`.
- `commands/` Tauri command handlers: `settings.rs` (every `change_*_setting`),
  `audio.rs`, `models.rs`, `history.rs`, `meeting.rs`, `mod.rs` (app dirs).
- `managers/` core logic: `audio.rs` recording and devices, `model.rs` model
  catalog and downloads (Hugging Face only), `transcription.rs` Whisper via
  `transcribe-cpp`, `history.rs` dictation history (SQLite), `meeting.rs`
  meetings (SQLite).
- `audio_toolkit/` device enumeration, resampling, Silero VAD, filler words.
- `kantega_llm.rs` the only HTTP client for LLM calls: `complete()` and
  `summarize()`. Never call any other LLM endpoint.
- `actions.rs`, `transcription_coordinator.rs` shortcut actions and the
  recording state machine.
- `shortcut/` global shortcuts via `handy-keys`. `secure_input.rs` macOS
  Secure Input detection with a Carbon fallback.
- `clipboard.rs`, `input.rs` paste via clipboard + Cmd/Ctrl+V (enigo).
- `overlay.rs` recording pill window. `tray.rs`, `tray_i18n.rs` tray icon and
  menu; tray strings are generated by `build.rs` from the `tray.*` i18n keys.
- `catalog/catalog.json` the Whisper model catalog.

### Frontend `src/`

- `App.tsx` onboarding gate, page header, toasts.
- `components/Sidebar.tsx` sections, grouped: Bruk (meeting, history),
  Innstillinger (general, models, postprocessing, advanced), about. Meeting is
  the start screen.
- `components/settings/<pane>/` one directory per pane; shared setting rows in
  `components/settings/*.tsx`. `LlmApiKeyField.tsx` is the single key field
  used by Meeting and Post-processing.
- `components/ui/` primitives: `SettingsGroup`, `SettingContainer` (title +
  always-visible description + control), `ToggleSwitch`, `Button`, `Input`,
  `Textarea`, `Dropdown`, `Dialog`, `EditableText`, `ExportMenu`, `AudioPlayer`.
- `stores/settingsStore.ts` Zustand store; `settingUpdaters` maps each setting
  key to its Tauri command. Initialised once in `main.tsx`.
- `stores/modelStore.ts`, `stores/meetingStore.ts`.
- `lib/export/` Markdown, DOCX, PDF export. `lib/constants/languages.ts`
  selectable languages: auto, nb, en.
- `overlay/` the recording overlay window entry.

### Settings that matter

- `post_process_enabled` post-process every dictation automatically. The
  `transcribe_with_post_process` shortcut post-processes one dictation
  regardless. `post_process_prompt`. `llm_model` is the one LLM model, set in the Models pane.
- `meeting_auto_summarize` summarise a meeting right after transcription.
  `meeting_summary_prompt`. `summarize_meeting` also
  accepts a per-meeting prompt override.
- `llm_api_keys["kantega_llmproxy"]` the one API key. Empty string removes it.

## i18n

All user-facing strings go through i18next; ESLint rejects literals in JSX.
Two locales, `en` (source) and `nb`. Every key must exist in both files under
`src/i18n/locales/`, checked by `bun run check:translations`. Delete keys from
both files when their code goes. The `tray.*` keys are a build input for
`build.rs`.

## Code style

**Rust:** `cargo fmt` and `cargo clippy` clean. `anyhow` with context, `?`
propagation, no `unwrap` on reachable paths. `Arc<Mutex<T>>` for manager state.
Doc comments on public items.

**TypeScript:** strict, no `any`, `React.FC<Props>`, `interface` for shapes,
`useCallback` for callbacks passed as props, Tailwind, `@/` alias, type-only
imports. Optimistic updates roll back on failure.

**Both:** no history comments ("previously", "used to", "removed X"). No
legacy fallbacks or migrations kept after they have expired.

## CLI

| Flag                     | Effect                                 |
| ------------------------ | -------------------------------------- |
| `--toggle-transcription` | Toggle recording on a running instance |
| `--toggle-post-process`  | Toggle recording with post-processing  |
| `--cancel`               | Cancel the current operation           |
| `--start-hidden`         | Launch without the main window         |
| `--no-tray`              | Launch without tray icon               |
| `--debug`                | Trace logging                          |

Headless (no mic, no download, exits when done): `-f/--transcribe-file <WAV>`,
`--model <ID>`, `--device-index <N>`, `--list-devices`, `--list-models`,
`--repeat <N>`, `--json`.

Remote-control flags work through `tauri_plugin_single_instance`: the second
instance forwards its args and exits. CLI flags never change persisted settings.
